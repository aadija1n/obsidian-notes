The Python execution process involves a hybrid compiler-interpreter model to convert source code into machine instructions. This process is divided into two major phases :
1. **Compilation Stage** ( Source code to Bytecode ) : the built-in python compiler parses the source code file (.py) and running it through multiple checks - it generates a bytecode for next stage. This stage is responsible for finding syntax errors before execution.<br><br>
	- **Lexical Analysis** ( Tokenization ) : the compiler scans the source code text character-by-character, stripping out whitespaces and comments. It breaks the text into Tokens (keywords, operators, literals, etc).
	- **Parsing and Abstract Syntax Tree (AST)** : compiler organizes the tokens into an Abstract Syntax Tree (AST), checking that the code follow python rules. any structural violation immediately throws a syntax error and stops the execution.
	- **Byteode Generation** : the compiler translates the validated AST into bytecode, which consist of platform-independent, low-level operational codes (opcodes).
	- **Caching the Bytecode** : python caches this bytecode into a .pyc files , which is located inside `__pycache__` folder. on next execution python uses same bytecode and skips the compilation stage if no changes have been made. This make execution faster after first execution.
<br>


2. **Interpretation / Execution Stage** : the core engine of python runtime is Python Virtual Machine (PVM). The PVM acts as a large loop that continuously fetches, decodes, and processes the bytecode instructions sequentially (line-by-line). <br><br>
	- **The Interpreter loop** : pvm operates a massive evaluation stack. it pulls each bytecode instruction line-by-line and dispatches it to a corresponding internal implementation function (typically written in C - for standard CPython).
	- **Memory and Object Mapping** : dynamic object mapping occurs during this phase. when encountering an assignment like `x = 10`, the PVM requests space from the heap memory via operating system primitives, generates a PyObject structure, and points the variable name to that memory address.
	- **Interaction with Host System** : The underlying C implementation functions convert this generalized bytecode tasks into system calls for windows, macos, or linux. the operating system kernel routes these resulting binary instructions to the CPU, delivering the output.
<br>

```
[ .py Source Code ]

        v

1. Compilation Stage (Tokenizing —» Parsing —» AST —» Bytecode)

        v

[ .pyc Bytecode File ] (Stored in _pycache_)

        v

2. Execution Stage (Python Virtual Machine Loop —= C Runtime Functions)

        v

[ 05 System Calls / CPU Native Machine Code ]
```
---
The above process maps to the standard CPython - distributed on python.org. Other implementations of python might differ in the execution process.
- **CPython** : Translates code to bytecode, and interprets it sequentially. it does not compile straight to native assembly code.
- **PyPy** : Uses a Just-in-Time (JIT) compiler. as the bytecode runs, the JIT analyzer spots frequently repeated routines (hot code) and transforms the hot code directly into machine code at runtime. this compiled code is reused, avoiding repeated interpretation. This approach optimizes execution speed for heavily mathematical or repetitive applications.
